# docset — 가상 프로젝트 합성 데이터셋 (DATA-01)

가상 SI 프로젝트 2개(A·B)의 산출물과 변경 이력, 정답을 모아 둔 폴더다. 우리 서비스가 다루는 흐름(제출 → 파싱 → diff → 영향 판정 → 알림 → 챗봇·MCP)을 **최종 평가 전에 만들고, 조정하고, 연습하는 용도**로 쓴다.

> 실존 회사·인물과 무관한 가상 데이터다. 모든 파일은 `build_docset.py`로 생성한다. 엑셀을 직접 고치지 말고 py 파일을 고친 뒤 다시 생성한다.

## 한눈에 보기

| 데이터셋 | 내용 | 용도 |
|---|---|---|
| **A** 가나유통 온라인몰 차세대 구축 (`26.11.19쇼핑몰A`) | 문서 14종(xlsx·docx·pptx·md), 버전 v1~v3, 실제 변경 10건, 시나리오 53건, 질문 100개 | 학습·조정 |
| **B** 다온정밀 구매·발주 시스템 (`26.11.20구매B`) | 문서 14종(xlsx·docx·pptx·md·**hwpx·pdf·txt**), 버전 v1~v4, 실제 변경 27건(대리 승인 포함), 시나리오 43건, 질문 70개 | 학습·조정, 파일 형식 다양성, 병합·수식 엑셀 파싱, A·B 구분 질문 |
| **C** 테스트셋 (아직 없음) | 사람이 직접 만든 변경 시나리오 + 라벨 | **최종 평가 전용** |

- **A·B는 테스트셋이 아니다.** 프롬프트, 파싱 규칙, 판정 방식을 고르고 조정하는 데 쓴다. A·B에서 나온 점수는 발표·보고 수치로 쓰지 않는다.
- **최종 점수는 C에서만 낸다.** 조건은 다음과 같다.
  - C 시나리오는 사람이 직접 작성한다(DATA-03).
  - 라벨은 **시나리오 작성자가 아닌 2명**이 따로 붙이고, 일치도(kappa)를 잰다(DATA-04).
  - 라벨은 **테스트 전에 확정하고 동결**한다. 테스트 중에는 라벨을 보지 않는다.

## 폴더 구조

```
docset/
├─ 1_문서세트/                 RAW 문서 + 그 정답지
│  ├─ 회사_인원풀.xlsx
│  ├─ 26.11.19쇼핑몰A/
│  │  ├─ 00_프로젝트개요_팀구성.md
│  │  ├─ v1/  v2/  v3/         버전별 HEAD 문서
│  │  ├─ 승인대기/  반려/       HEAD가 아닌 제출본
│  │  ├─ 문서이력.xlsx
│  │  └─ 변경이력_정답.xlsx
│  └─ 26.11.20구매B/            (A와 같은 구성, v4까지)
├─ 2_질문셋/
│  ├─ 26.11.19쇼핑몰A_질문셋.xlsx
│  └─ 26.11.20구매B_질문셋.xlsx
├─ 3_변경시나리오/              학습·조정용 가상 변경 + 정답
│  ├─ 26.11.19쇼핑몰A_변경시나리오_라벨.xlsx
│  ├─ 26.11.19쇼핑몰A_시나리오문서/   제출본 파일 53개
│  ├─ 26.11.20구매B_변경시나리오_라벨.xlsx
│  └─ 26.11.20구매B_시나리오문서/     제출본 파일 43개
└─ *.py                         데이터 원본과 생성기
```

## 파일별 설명

### 1_문서세트/ — RAW 문서와 그 정답지

서비스에 실제로 올라가는 문서들이다. 정답지(`변경이력_정답.xlsx`)는 이 폴더의 문서에서 **실제로 일어난 변경**에 대한 것이다.

| 파일·폴더 | 무엇인가 | 어디에 쓰나 |
|---|---|---|
| `v1/` | 문서 14종의 첫 버전(기준선) | 서비스에 처음 올리는 HEAD. 파싱·전처리 조정(CHG-01·02), 임베딩(CHG-05), 챗봇·MCP 검색 대상 |
| `v2/`, `v3/` (B는 `v4/`까지) | 승인된 변경으로 새 버전이 생긴 문서만 들어 있다. 문서별 최신본(HEAD)은 가장 높은 버전 | 버전 비교·diff 조정(CHG-04), 변경 보기 시연, "최신본이 뭐야?" 같은 질문의 정답 근거 |
| `승인대기/` | 아직 승인되지 않은 제출본 (A: CHG-009, B: CHG-B26·B27) | 승인 화면 시연. **챗봇·MCP 검색에서 빠지는지** 확인 (이 내용으로 답하면 오류) |
| `반려/` | 반려된 제출본 (A: CHG-008, B: CHG-B22) | 반려 이력 시연, 검색 제외 확인 |
| `문서이력.xlsx` | ① HEAD 현황: 문서별 최신 버전, 공개 범위, 승인자 ② 변경 요청: 변경별 상태·작성자·승인자·반려 사유 | 서비스 DB 초기 데이터(문서·버전·승인 이력). "누가 언제 바꿨어?" 같은 변경 이력 질문의 정답 |
| `변경이력_정답.xlsx` | 실제 변경(A 10건, B 27건)의 정답. 시트 4개: <br>• **변경 상세(diff)**: 버전 사이에 바뀐 칸의 이전·이후 값 <br>• **영향 팀 라벨**: 변경 × 팀별 영향 있음/없음과 근거 <br>• **반복값 위치(HEAD)**: 같은 규칙(무료배송 기준, 비밀번호 길이 등)이 어느 문서 어느 위치에 적혀 있는지 | diff 정답은 파이프라인 채점(**한 문서에서 여러 군데가 한꺼번에 바뀐** 어려운 경우). 라벨은 라벨 가이드 경계 사례, 판정 연습. 반복값 위치는 시나리오를 쓸 때 영향 범위를 찾는 참고 지도 |
| `00_프로젝트개요_팀구성.md` | 프로젝트 소개, 팀·역할·사번, 문서 목록, 변경 요약, 문서마다 값이 다른 곳(⚠️) | **사람이 읽는 안내문.** 데이터를 처음 볼 때 먼저 읽는다. 서비스에는 올리지 않는다 |
| `회사_인원풀.xlsx` | 가상 회사 직원 명단, 프로젝트별 배치(A·B), 발주처 게스트 | 서비스 계정·조직·권한 초기 데이터. 권한 테스트에서 "누가 무엇을 볼 수 있나"의 근거 |

**일부러 넣은 불일치:** 이게 서비스가 해결하려는 **변경 전파 누락**이다. 버그가 아니다.
- A: 요구사항정의서에서 무료배송 기준을 50,000원에서 70,000원으로 바꿨지만, 일부 문서에는 아직 50,000원이 남아 있다.
- B: 구매정책기준서 값이 바뀐 뒤 일부 문서가 따라가지 못했다. 단가 유효기간(IF-009는 6개월), 수량 허용 오차(SCR-011·IF-016·TC-024는 ±2%), 표준 리드타임(업무프로세스 BR-08·TB_PO_ITEM·TC-014는 7영업일).

**B만의 특징**
- **파일 형식 7종:** xlsx·docx·pptx·md에 더해 구매정책기준서·연계정의서는 hwpx, 아키텍처 설계서·테스트계획서는 텍스트 PDF, 데이터이행계획서는 txt다.
- **파싱이 까다로운 엑셀 2종:** `WBS_일정표`('1. WBS' 시트)와 `테스트케이스_결과서`('3. 수행 요약' 시트)는 일부러 실무 엑셀처럼 만들었다.
  - 2단 병합 헤더(일정 → 시작·종료), 단계 열 세로 병합(첫 행 아래는 빈 칸)
  - 단계별 소계 행·전체 행이 데이터 사이에 끼어 있음(SUM·AVERAGE 수식, 같은 이름 소계가 두 번 나옴)
  - 날짜는 진짜 날짜 셀, 진척률은 0.85에 % 서식, 숨김 열(K 가중치)
  - 다른 시트를 집계하는 COUNTIFS 수식
  - 수식 셀에는 계산값도 들어 있다. openpyxl로 읽으면 수식 문자열, `data_only=True`면 계산값이 나온다.
- **대리 승인:** 팀마다 대리 승인자가 있다. 팀장이 쓴 문서는 대리 승인자가 승인하고(본인 승인 금지), 팀장 휴가 중 대리 승인한 변경도 2건 있다(CHG-B17·B19). `문서이력.xlsx`의 '승인 구분' 열에 표시된다.
- **A·B 동시 수행 인원:** 7명이 두 프로젝트에 다른 역할로 배치돼 있다(`회사_인원풀.xlsx`).

### 2_질문셋/ — 챗봇·MCP 질문

| 파일 | 무엇인가 | 어디에 쓰나 |
|---|---|---|
| `26.11.19쇼핑몰A_질문셋.xlsx` | 질문 100개(미지정 5개 포함). 질문마다 다음이 적혀 있다. <br>• 의도 6종: 내 할 일, 내용 질의, 범위 밖, 변경 이력, 영향 질문, 최신본 조회 <br>• 유형: 단일·복합·애매·범위 밖 <br>• 질문자(사번·팀·역할), 관련 문서, 정답 비고 <br>권한 밖 질문(게스트, 프로젝트 밖 직원)도 들어 있다 | 질문 의도 분류 조정·학습(EXP-05), 챗봇 답변·출처 확인, 권한 필터 점검. LLM이 만든 질문이라 **최종 평가용이 아니다** |

| `26.11.20구매B_질문셋.xlsx` | 질문 70개(B 65 + 미지정 5). 열 구성은 A와 같다. 정책값 불일치를 묻는 질문, 대리 승인·반려 이력, hwpx·pdf 문서, 팀 내부 문서 권한 질문이 들어 있다 | A와 같음 |

- **프로젝트 '미지정' 질문 5개**는 A·B 파일에 똑같이 들어간다. A·B를 함께 하는 사람이 프로젝트를 밝히지 않고 묻는 질문이다(예: 윤하린의 "내가 승인해야 할 요청 몇 건이야?" → A 1건, B 1건). 질문자 정보(팀·역할)는 그 파일 프로젝트의 배치로 풀어 적었다.
- 질문 ID(Q001…)는 파일마다 따로 매긴다.

### 3_변경시나리오/ — 학습·조정용 가상 변경

1_문서세트의 HEAD를 바탕으로 "이 문서가 이렇게 바뀌면?"을 만든 가상 변경이다. **학습·조정은 주로 여기로 한다.**

| 파일·폴더 | 무엇인가 | 어디에 쓰나 |
|---|---|---|
| `26.11.19쇼핑몰A_변경시나리오_라벨.xlsx` | 시나리오 53건(TR-A-001~053)과 정답. 시트는 다음과 같다. <br>• **시나리오**: 문서, 위치, 이전→이후, 변경 사유, 기준 버전, 제출본 파일 <br>• **변경 상세(diff)**: HEAD 대비 바뀐 칸 74칸 <br>• **영향 라벨**: 시나리오 × 팀 318쌍, 영향 있음 86쌍(27%), 경계 사례 표시 <br>• **분포** | diff 정답은 파이프라인 채점. 영향 라벨은 판정 프롬프트 조정(IMP-01·02), 로지스틱 회귀 학습(EXP-02), 판정 방식 비교 연습(EXP-01). 3줄 요약 프롬프트 조정 입력으로도 쓴다 |
| `26.11.19쇼핑몰A_시나리오문서/` | 시나리오별 제출본 파일 53개 (`TR-A-001_01_요구사항정의서.xlsx` …) | 파싱 → diff → 판정 전체 흐름 시험의 입력 |
| `26.11.20구매B_변경시나리오_라벨.xlsx` | 시나리오 43건(TR-B-001~043), 시트 구성은 A와 같다. diff 51칸, 시나리오 × 팀 215쌍, 영향 있음 62쌍(29%), 경계 사례 41쌍 | A와 같음. 정책값 불일치를 **바로잡는** 시나리오와 **더 벌리는** 시나리오가 섞여 있다 |
| `26.11.20구매B_시나리오문서/` | 제출본 파일 43개 — xlsx 19, docx 8, hwpx 8, pdf 4, pptx 3, txt 1. WBS·TC 시나리오 파일도 병합·수식 형식 그대로다 | 형식별 파싱 → diff 시험 |

**시나리오 파일 만드는 방식**
- 파일 하나는 HEAD 문서 전체를 복사한 뒤, 그 시나리오의 변경 **한 군데만** 바꾼 것이다. 예: TR-A-001은 요구사항정의서 v3에서 FR-003의 "5회 연속" → "3회 연속"만 다르다.
- 53건은 **서로 독립**이다. 모두 같은 HEAD에서 출발하고, 서로의 변경이 쌓이지 않는다.
- 예외(여러 칸이 바뀌는 경우):
  - TR-A-019: 요구사항을 추가하면 추적표 행도 함께 생겨서 19칸이 바뀐다.
  - TR-A-039: 같은 값이 한 문서에 두 번 있어서 2칸이 바뀐다.
  - TR-B-018: 정책서의 "5,000만원 이상"이 표와 본문에 함께 있어서 4칸이 바뀐다.
  - TR-B-035: 테이블정의서에 컬럼을 추가하면 컬럼 정의 행 1개가 생겨 6칸이 바뀐다.

**라벨 상태:** LLM이 만든 초안이다. 사람이 '검수자'·'검수 결과' 칸을 채운 뒤에 쓴다. 라벨 기준은 엑셀의 '안내' 시트와 `train_a.py`·`train_b.py` 맨 위에 있다(B는 A 기준을 B 조직에 맞춘 것).

### py 파일 — 데이터 원본과 생성기

| 파일 | 무엇인가 |
|---|---|
| `project_a.py`, `project_b.py` | 프로젝트의 모든 내용을 데이터로 적어 둔 파일(요구사항·화면·인터페이스·테이블·TC·실제 변경·영향 라벨). 문서 생성의 원본이자 **추출 정확도 채점의 정답지**(ID 재현율, 표 셀 정확도) |
| `train_a.py`, `train_b.py` | A 시나리오 53건, B 시나리오 43건과 라벨. 라벨을 고칠 때는 여기서 고친다 |
| `questions.py` | 질문 165개(A 95, B 65, 미지정 5). 프로젝트 열로 나눠 질문셋 파일을 따로 만든다 |
| `company.py` | 회사 직원 명단 (A·B가 같은 직원을 공유) |
| `build_docset.py` | 생성기. 위 파일을 읽어 엑셀·워드·PPT·한글·PDF·텍스트를 만들고, 참조가 끊긴 곳이 없는지 검사(`check()`)한다. hwpx·pdf는 표준 라이브러리로 만든다(추가 패키지 없음) |

## 다시 생성하기

생성 전에 엑셀 파일을 모두 닫는다. 열려 있으면 덮어쓰기에 실패한다.

macOS (zsh)
```bash
cd data/docset
uv run --with python-docx --with python-pptx --with openpyxl python build_docset.py
```

Windows (PowerShell)
```powershell
cd data\docset
$env:PYTHONIOENCODING="utf-8"; uv run --with python-docx --with python-pptx --with openpyxl python build_docset.py
```

`1_문서세트/<프로젝트>/`와 `<프로젝트>_시나리오문서/` 폴더 안의 내용은 생성할 때마다 지우고 다시 만든다.

## 할 일별로 어떤 자료를 쓰나

| 하는 일 | 입력 | 정답 |
|---|---|---|
| 파싱·추출 품질 | `1_문서세트`의 v1~ 문서 | `project_a.py` / `project_b.py`의 원본 데이터 |
| diff (실제 변경, 여러 군데) | v1→v2→v3 문서 | `변경이력_정답.xlsx` → 변경 상세(diff) |
| diff (시나리오, 한 군데) | HEAD + `시나리오문서/` 파일 | `변경시나리오_라벨.xlsx` → 변경 상세(diff) |
| 영향 판정 조정·학습 | 시나리오 변경 내용(필요하면 실제 변경도) | `변경시나리오_라벨.xlsx` → 영향 라벨 (+ `변경이력_정답.xlsx` → 영향 팀 라벨) |
| 3줄 요약 조정 | 시나리오·실제 변경 | 정답 없음. 사람이 보고 판단 |
| 질문 의도·챗봇·MCP | HEAD 문서 + 질문셋 | 질문셋의 의도·비고 열 |
| 권한 필터 | 인원풀 + 문서 공개 범위 + 권한 밖 질문 | 문서이력(공개 범위), 인원풀(배치) |
| **최종 평가** | **C** | **C 라벨 (작성자 외 2명, 테스트 전 확정)** |

## 팀원별로 전할 내용

### 문서 처리 파이프라인 담당 (CHG-01·02·04·05)
- **파싱·추출 조정**: `1_문서세트`의 v1 문서로 한다. B는 hwpx·pdf·txt까지 있어서 형식별 파서를 시험할 수 있다. B의 `WBS_일정표`·`테스트케이스_결과서`는 병합 셀·소계 수식·숨김 열이 있는 엑셀이라 엑셀 전처리(병합 채우기, 2단 헤더 합치기, 소계 행 제외, 수식/계산값 선택)를 확인하는 데 쓴다. 추출이 맞았는지는 `project_a.py`·`project_b.py`의 원본 데이터와 비교해서 숫자로 잰다(ID 재현율, 표 셀 정확도).
- **diff 조정**:
  - 실제 변경(v1→v2→v3, 한 문서에서 여러 군데 변경)의 정답은 `변경이력_정답.xlsx`에 있다.
  - 시나리오(A 53건, B 43건, 한 군데 변경)의 정답은 `변경시나리오_라벨.xlsx`의 '변경 상세(diff)' 시트에 있다.
  - 정답은 **칸(셀·문단) 단위** 이전·이후 값이다.
- **비교 대상**: 파이프라인 출력은 영향 라벨이 아니라 **diff 정답**과 비교한다.
- **넘겨 줄 것**: diff 결과를 정답 시트와 같은 열(위치, 항목, 이전 값, 이후 값)로 내 주면 판정 쪽에서 바로 이어서 쓸 수 있다.

### 질의응답 에이전트·MCP 담당 (CHAT, MCP, EXP-05·07)
- 검색 대상은 **v1~ 버전 폴더의 HEAD 문서뿐**이다. `승인대기/`·`반려/` 내용으로 답하면 오류다.
- 질문셋(A 100개, B 70개)으로 의도 분류, 출처 표시, 권한 밖 질문 거절을 확인한다. '미지정' 질문으로 A·B 동시 수행 인원의 질문을 어느 프로젝트로 풀지 확인한다.
- A와 B를 함께 올려 두고, 주어 없는 질문("무료배송 기준이 얼마야?")을 질문자의 프로젝트로 맞게 해석하는지 확인한다.
- 문서마다 값이 다른 항목(무료배송 50,000 vs 70,000)은 **최신 HEAD 값**과 출처로 답해야 한다.

### 백엔드 담당 (인증·조직·문서·승인)
- 초기 데이터:
  - `회사_인원풀.xlsx`: 직원, 프로젝트 배치, 게스트
  - `문서이력.xlsx`: 문서, 버전, 공개 범위, 승인 이력
- 지켜야 할 규칙: **본인 승인 금지**(팀장이 쓴 문서는 대리 승인자가 승인), 공개 범위 4단계, 게스트는 '외부 공유' 문서만 볼 수 있다.
- 알림 응답 버튼은 **작업 필요 / 해당 없음**이다.

### C 테스트셋 작성자·라벨러
- A·B 시나리오 형식(`변경시나리오_라벨.xlsx`의 열 구성)을 그대로 쓰되, 내용은 **사람이 직접** 쓴다.
- 시나리오 작성자는 라벨링에 참여하지 않는다. 라벨러 2명이 서로 보지 않고 따로 붙인다.
- 라벨은 테스트 전에 확정하고 동결한다.
- 라벨 기준(요약, 전체는 `train_a.py`·`train_b.py` 맨 위):
  1. **영향 있음** = 그 팀이 자기 문서나 코드를 **고쳐야 한다**. 알아 두기만 하면 되는 것은 영향 없음.
  2. 화면의 고정 문구·배지·maxlength는 디자인&퍼블리싱, 오류·안내 메시지와 검증 로직은 그 화면 담당 개발팀. 퍼블리싱 '대기' 화면은 디자인 영향 없음(경계).
  3. QA는 기존 TC의 입력·기대 결과가 바뀔 때만 영향 있음.
  4. 일정이 늦춰지기만 하면 영향 없음.
  5. 하위 문서가 상위 요구사항과 어긋나게 바뀌면 상위 문서 소유 팀이 영향 있음.
  6. 문서 소유 팀은 판정 대상이 아니다(항상 알림). '팀 내부' 문서는 다른 팀 판정 대상이 아니다.
